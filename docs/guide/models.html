Models ​

Models are the core building block of mobx-data. Each model class represents a type of resource (e.g., User, Post, Comment) and defines its attributes and relationships using decorators.

Defining a Model ​

ts
import { Model, attr, belongsTo, hasMany } from 'mobx-data';

class Article extends Model {
  static modelName = 'article';

  @attr('string') declare title: string;
  @attr('string') declare body: string;
  @attr('number') declare wordCount: number;
  @attr('date') declare publishedAt: Date;
  @attr('boolean') declare isDraft: boolean;

  @belongsTo('user') declare author: User;
  @hasMany('comment') declare comments: Comment[];
}

Every model must declare a static modelName — this is the key used by the store, adapters, and serializers to identify the type.

Attributes ​

The @attr decorator marks a property as a serializable attribute:

ts
@attr('string') declare name: string;
@attr('number', { defaultValue: 0 }) declare score: number;
@attr('date') declare createdAt: Date;
@attr('boolean') declare isActive: boolean;

Custom Transforms ​

Register custom transforms for complex types:

ts
import { Transform } from 'mobx-data/transforms';

const currencyTransform: Transform<number, string> = {
  serialize(value: number): string {
    return value.toFixed(2);
  },
  deserialize(raw: string): number {
    return parseFloat(raw);
  },
};

store.registerTransform('currency', currencyTransform);

// Usage
@attr('currency') declare price: number;

Record Lifecycle ​

Every record has observable state properties:

PropertyTypeDescription
isNewbooleanCreated locally, not yet persisted
isDirtybooleanHas unsaved changes
isSavingbooleanSave request in flight
isLoadingbooleanLoad request in flight
isLoadedbooleanSuccessfully loaded from server
isDeletedbooleanMarked for deletion
isErrorbooleanLast operation failed
isValidbooleanNo validation errors

Dirty Tracking ​

mobx-data tracks changes at the attribute level:

ts
const user = store.peekRecord('user', '1');

user.name = 'New Name';
console.log(user.isDirty);         // true
console.log(user.dirtyAttributes); // ['name']

user.rollbackAttributes();
console.log(user.name);            // original value
console.log(user.isDirty);         // false

Lifecycle Hooks ​

Override these methods to react to state transitions:

ts
class User extends Model {
  static modelName = 'user';

  @attr('string') declare name: string;

  didLoad(): void {
    console.log(`${this.name} loaded from server`);
  }

  didCreate(): void {
    console.log(`${this.name} created on server`);
  }

  didUpdate(): void {
    console.log(`${this.name} updated on server`);
  }

  didDelete(): void {
    console.log(`${this.name} deleted from server`);
  }

  willSave(): void {
    // Called before any save operation
  }

  didSave(): void {
    // Called after successful save (create, update, or delete)
  }

  becameInvalid(errors: Errors): void {
    // Server returned validation errors
  }

  becameError(error: Error): void {
    // Non-validation error occurred
  }
}

Saving Records ​

ts
// Create and save
const post = store.createRecord('post', { title: 'Hello' });
await post.save(); // POST /posts

// Update and save
post.title = 'Updated Title';
await post.save(); // PATCH /posts/1

// Delete
await post.destroyRecord(); // DELETE /posts/1

Reloading ​

ts
// Reload from server
await user.reload();

Snapshots ​

Get a frozen view of a record's current state:

ts
const snapshot = user.createSnapshot();
console.log(snapshot.id);         // '1'
console.log(snapshot.attributes); // { name: 'Alice', age: 30 }
console.log(snapshot.belongsTo('team')); // { type: 'team', id: '5' }

Snapshots are passed to adapters and serializers during save operations — they never receive the live record.
