Relationships ​

mobx-data supports the same relationship types as Ember Data: belongsTo and hasMany, with both synchronous and asynchronous resolution strategies.

Defining Relationships ​

ts
import { Model, attr, belongsTo, hasMany } from 'mobx-data';

class User extends Model {
  static modelName = 'user';

  @attr('string') declare name: string;
  @hasMany('post', { inverse: 'author' }) declare posts: Post[];
  @belongsTo('team', { async: true }) declare team: Team;
}

class Post extends Model {
  static modelName = 'post';

  @attr('string') declare title: string;
  @belongsTo('user', { inverse: 'posts' }) declare author: User;
  @hasMany('comment') declare comments: Comment[];
}

belongsTo ​

A belongsTo defines a many-to-one relationship — the record holds a reference to a single related record.

ts
@belongsTo('user') declare author: User;
@belongsTo('team', { async: true }) declare team: Team;
@belongsTo('category', { inverse: null }) declare category: Category;

Options ​

OptionTypeDefaultDescription
asyncbooleanfalseWhether to return an async proxy
inversestring | nullauto-detectedThe inverse relationship name on the related model
polymorphicbooleanfalseWhether the related type can vary

Sync vs Async ​

Sync (default) — returns the record directly if loaded, or null:

ts
const author = post.author; // User | null

Async — returns an AsyncBelongsTo proxy that triggers a fetch:

ts
const team = await user.team; // fetches if not loaded

hasMany ​

A hasMany defines a one-to-many relationship — the record holds references to multiple related records.

ts
@hasMany('post', { inverse: 'author' }) declare posts: Post[];
@hasMany('tag', { async: true }) declare tags: Tag[];

Options ​

OptionTypeDefaultDescription
asyncbooleanfalseWhether to return an async proxy
inversestring | nullauto-detectedThe inverse relationship name

Sync hasMany ​

Returns a ManyArray — an observable array-like object:

ts
const posts = user.posts; // ManyArray<Post>
console.log(posts.length);
posts.forEach(post => console.log(post.title));

Async hasMany ​

Returns an AsyncHasMany proxy that fetches related records on access:

ts
const tags = await post.tags; // fetches from server

Inverse Relationships ​

When you mutate one side of a relationship, the other side updates automatically:

ts
const user = store.peekRecord('user', '1');
const post = store.createRecord('post', { title: 'New' });

// Setting the belongsTo...
post.author = user;

// ...automatically updates the hasMany
console.log(user.posts.includes(post)); // true

Explicit Inverses ​

ts
class Folder extends Model {
  static modelName = 'folder';

  @belongsTo('folder', { inverse: 'children' }) declare parent: Folder;
  @hasMany('folder', { inverse: 'parent' }) declare children: Folder[];
}

No Inverse ​

Use inverse: null to opt out of inverse tracking:

ts
@belongsTo('user', { inverse: null }) declare createdBy: User;

Modifying Relationships ​

belongsTo ​

ts
// Set
post.author = user;

// Clear
post.author = null;

hasMany ​

ManyArray supports standard array mutations:

ts
// Add
user.posts.pushObject(newPost);

// Remove
user.posts.removeObject(oldPost);

// Replace all
user.posts = [post1, post2];

Loading Strategies ​

Sideloading ​

If the API response includes related records, they're pushed into the identity map automatically:

json
{
  "user": { "id": "1", "name": "Alice", "posts": ["10", "11"] },
  "posts": [
    { "id": "10", "title": "First" },
    { "id": "11", "title": "Second" }
  ]
}

Lazy Loading (Async) ​

Async relationships trigger a fetch when first accessed if the related records aren't in the identity map.

Eager Loading ​

Pass include to fetch related records in a single request:

ts
const user = await store.findRecord('user', '1', {
  include: 'posts,posts.comments',
});

The adapter translates include into the appropriate query parameter for your API format (e.g., ?include=posts,posts.comments for JSON:API).
