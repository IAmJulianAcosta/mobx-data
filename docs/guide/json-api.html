JSON:API ​

mobx-data includes first-class support for the JSON:API specification. The json-api module provides both an adapter and a serializer that handle the full spec.

Setup ​

ts
import { Store } from 'mobx-data';
import { JsonApiAdapter, JsonApiSerializer } from 'mobx-data/json-api';

const store = new Store();

store.registerAdapter('application', new JsonApiAdapter({
  host: 'https://api.example.com',
}));

store.registerSerializer('application', new JsonApiSerializer());

JSON:API Document Format ​

The serializer handles the standard JSON:API document structure:

json
{
  "data": {
    "type": "articles",
    "id": "1",
    "attributes": {
      "title": "Hello World",
      "body": "Content here..."
    },
    "relationships": {
      "author": {
        "data": { "type": "people", "id": "5" }
      },
      "comments": {
        "data": [
          { "type": "comments", "id": "10" },
          { "type": "comments", "id": "11" }
        ]
      }
    }
  },
  "included": [
    {
      "type": "people",
      "id": "5",
      "attributes": { "name": "Alice" }
    }
  ]
}

Features ​

Compound Documents (Sideloading) ​

Records in the included array are automatically pushed into the identity map:

ts
const article = await store.findRecord('article', '1', {
  include: 'author,comments',
});

// Author and comments are already in the store
const author = store.peekRecord('person', '5'); // already loaded

Sparse Fieldsets ​

Request only specific fields:

ts
const users = await store.query('user', {
  fields: { user: 'name,email', post: 'title' },
});

Generates: GET /users?fields[user]=name,email&fields[post]=title

Pagination ​

ts
const page1 = await store.query('post', {
  page: { number: 1, size: 25 },
});

// Access pagination links from the response
const nextLink = page1.links?.next;

Filtering ​

ts
const results = await store.query('article', {
  filter: {
    author: '5',
    published: true,
  },
});

Generates: GET /articles?filter[author]=5&filter[published]=true

Sorting ​

ts
const sorted = await store.query('article', {
  sort: '-publishedAt,title', // descending publishedAt, ascending title
});

Include (Eager Loading) ​

ts
const article = await store.findRecord('article', '1', {
  include: 'author,comments.author',
});

Error Handling ​

JSON:API errors are parsed and mapped to the record's errors collection:

json
{
  "errors": [
    {
      "status": "422",
      "source": { "pointer": "/data/attributes/title" },
      "title": "Invalid Attribute",
      "detail": "Title must be at least 3 characters"
    }
  ]
}
ts
try {
  await post.save();
} catch {
  post.errors.get('title'); // ['Title must be at least 3 characters']
}

Adapter Specifics ​

Content-Type ​

The JsonApiAdapter automatically sets:

  • Content-Type: application/vnd.api+json
  • Accept: application/vnd.api+json

URL Conventions ​

By default, JSON:API uses dasherized, pluralized URLs:

findRecord('blog-post', '1') → GET /blog-posts/1
findAll('user')              → GET /users

Relationship URLs ​

The adapter supports fetching relationship links:

GET /articles/1/relationships/author
GET /articles/1/author
