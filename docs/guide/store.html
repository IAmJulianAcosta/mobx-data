Store ​

The Store is the central coordinator of mobx-data. It manages the identity map, delegates to adapters and serializers, and provides the API for finding, creating, and saving records.

Creating a Store ​

ts
import { Store } from 'mobx-data';

const store = new Store();

Registration ​

Before using the store, register your adapters, serializers, and models:

ts
import { RestAdapter, JsonSerializer } from 'mobx-data';

// Application-wide defaults
store.registerAdapter('application', new RestAdapter({
  host: 'https://api.example.com',
}));
store.registerSerializer('application', new JsonSerializer());

// Per-model overrides
store.registerAdapter('user', new RestAdapter({
  host: 'https://auth.example.com',
}));

Lookup order: exact model name → 'application' fallback.

Finding Records ​

findRecord(modelName, id, options?) ​

Fetches a single record by ID. Always hits the server unless { reload: false } is passed.

ts
const user = await store.findRecord('user', '1');
const cached = await store.findRecord('user', '1', { reload: false });

findAll(modelName, options?) ​

Fetches all records of a type.

ts
const posts = await store.findAll('post');

query(modelName, params) ​

Sends a query to the adapter with arbitrary parameters.

ts
const results = await store.query('post', {
  filter: { author: '1' },
  sort: '-publishedAt',
  page: { number: 1, size: 10 },
});

queryRecord(modelName, params) ​

Like query, but expects a single record in the response.

ts
const currentUser = await store.queryRecord('user', { me: true });

Peeking (Synchronous Access) ​

These methods read from the identity map without triggering network requests:

ts
// Single record — returns record or null
const user = store.peekRecord('user', '1');

// All loaded records of a type
const allUsers = store.peekAll('user');

peekAll returns a live RecordArray — it updates reactively as records are added or removed.

Creating Records ​

ts
const post = store.createRecord('post', {
  title: 'New Post',
  body: 'Content here',
  author: store.peekRecord('user', '1'),
});

console.log(post.isNew); // true

await post.save(); // Persists to server

Pushing Data ​

Push pre-normalized data directly into the store (useful for WebSocket events or SSE):

ts
store.push({
  data: {
    type: 'user',
    id: '42',
    attributes: { name: 'Bob', age: 25 },
  },
});

If the record already exists in the identity map, it's updated in place — all existing references stay valid.

Unloading Records ​

Remove a record from the identity map without deleting it on the server:

ts
store.unloadRecord(user);

// Unload all records of a type
store.unloadAll('user');

Saving Records ​

The store provides saveRecord which is also available as record.save():

ts
await store.saveRecord(post);
// Equivalent to: await post.save();

The store determines whether to call adapter.createRecord or adapter.updateRecord based on record.isNew.

Live Arrays ​

peekAll and findAll return RecordArray instances — MobX observable arrays that automatically reflect the current contents of the identity map:

ts
const users = store.peekAll('user');

// Reactively updates when records are added/removed
autorun(() => {
  console.log(`${users.length} users loaded`);
});

Error Handling ​

ts
try {
  await store.findRecord('user', '999');
} catch (error) {
  if (error.status === 404) {
    console.log('User not found');
  }
}

For validation errors during save, the record transitions to an invalid state:

ts
try {
  await post.save();
} catch (error) {
  if (post.isValid === false) {
    console.log(post.errors.get('title')); // ['is required']
  }
}
