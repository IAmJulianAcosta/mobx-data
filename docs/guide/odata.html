OData ​

mobx-data includes an OData v4 adapter for connecting to Microsoft OData services and any API that follows the OData protocol.

Setup ​

ts
import { Store, JsonSerializer } from 'mobx-data';
import { ODataAdapter } from 'mobx-data/odata';

const store = new Store();

store.registerAdapter('application', new ODataAdapter({
  host: 'https://services.example.com',
  namespace: 'odata/v4',
}));

store.registerSerializer('application', new JsonSerializer());

URL Conventions ​

OData uses a different URL scheme than REST:

findRecord('user', '42')  → GET /odata/v4/Users('42')
findAll('user')           → GET /odata/v4/Users
query('user', { ... })    → GET /odata/v4/Users?$filter=...&$orderby=...

Query Options ​

Pass OData system query options through the query method:

$filter ​

ts
const activeUsers = await store.query('user', {
  $filter: "status eq 'active' and age gt 18",
});

// Or use a structured syntax:
const results = await store.query('user', {
  filter: { status: 'active', age: { gt: 18 } },
});

$orderby ​

ts
const sorted = await store.query('user', {
  $orderby: 'name asc, createdAt desc',
});

$select ​

ts
const partial = await store.query('user', {
  $select: 'name,email',
});

$expand (Relationships) ​

ts
const withPosts = await store.query('user', {
  $expand: 'posts($select=title,publishedAt)',
});

$top and $skip (Pagination) ​

ts
const page = await store.query('user', {
  $top: 25,
  $skip: 50, // page 3
});

Combined ​

ts
const results = await store.query('order', {
  $filter: "status eq 'pending'",
  $orderby: 'createdAt desc',
  $top: 10,
  $skip: 0,
  $expand: 'customer,items',
  $select: 'id,total,createdAt',
});

Responses ​

OData responses are typically wrapped in a value array:

json
{
  "@odata.context": "...",
  "@odata.count": 42,
  "value": [
    { "Id": "1", "Name": "Alice", "Email": "alice@example.com" },
    { "Id": "2", "Name": "Bob", "Email": "bob@example.com" }
  ]
}

The adapter/serializer handles this format automatically.

Customization ​

Custom Entity Paths ​

ts
class MyODataAdapter extends ODataAdapter {
  pathForType(modelName: string): string {
    // Override pluralization or casing
    return pascalCase(pluralize(modelName));
  }
}

Key Format ​

OData typically uses parenthesized keys. The adapter handles this:

/Users('42')        ← string key
/Orders(42)         ← numeric key
/Items(key1='a',key2='b')  ← composite key
