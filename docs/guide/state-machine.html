State Machine ​

Every mobx-data record has a built-in state machine that tracks its lifecycle. All state properties are MobX observables, so your UI can react to transitions automatically.

Full State List ​

StateDescription
emptyInitial placeholder — record instantiated but no data loaded
loadingAn adapter request is in flight
loaded.savedClean record — matches what the server last returned
loaded.created.uncommittedLocally created, not yet saved
loaded.created.inFlightCreate request in flight
loaded.updated.uncommittedDirty — has local changes
loaded.updated.inFlightUpdate request in flight
deleted.uncommittedMarked for deletion locally
deleted.inFlightDelete request in flight
deleted.savedSuccessfully deleted on server
errorA non-validation error occurred

Observable Flags ​

Rather than checking state strings directly, use the boolean flags:

ts
import { autorun } from 'mobx';

autorun(() => {
  if (record.isLoading) {
    showSpinner();
  } else if (record.isSaving) {
    showSavingIndicator();
  } else if (record.isError) {
    showError(record.adapterError);
  } else {
    showContent(record);
  }
});
FlagTrue when
isLoadingState is loading
isLoadedState starts with loaded
isNewState starts with loaded.created
isDirtyAttributes differ from last-known server state
isSavingState ends with inFlight
isDeletedState starts with deleted
isErrorState is error
isValiderrors collection is empty

Transitions ​

State transitions happen automatically as you interact with records:

ts
const post = store.createRecord('post', { title: 'Draft' });
// State: loaded.created.uncommitted
// isNew: true, isDirty: true

await post.save();
// State: loaded.saved
// isNew: false, isDirty: false

post.title = 'Updated';
// State: loaded.updated.uncommitted
// isDirty: true

await post.save();
// State: loaded.saved
// isDirty: false

await post.destroyRecord();
// State: deleted.saved
// isDeleted: true

Error Recovery ​

When an adapter operation fails:

ts
try {
  await post.save();
} catch (error) {
  // If validation error → record becomes invalid
  // post.isValid === false
  // post.errors contains field-level messages

  // If network/server error → record becomes errored
  // post.isError === true
  // post.adapterError contains the error
}

Recovering from Errors ​

ts
// Fix validation errors and retry
post.title = 'Valid Title';
await post.save(); // Transitions back to loaded.saved

// Or rollback
post.rollbackAttributes(); // Back to loaded.saved with original data

Validation Errors ​

The errors property is an observable Errors instance:

ts
if (!post.isValid) {
  // Get errors for a field
  const titleErrors = post.errors.get('title');
  // ['is required', 'must be at least 3 characters']

  // Check if a specific field has errors
  post.errors.has('title'); // true

  // Get all errors
  post.errors.toArray();
  // [{ attribute: 'title', message: 'is required' }, ...]

  // Clear errors (usually done automatically on next save)
  post.errors.clear();
}

React Integration ​

tsx
import { observer } from 'mobx-react-lite';

const SaveButton = observer(({ record }) => {
  if (record.isSaving) {
    return <button disabled>Saving...</button>;
  }

  if (!record.isDirty) {
    return <button disabled>No changes</button>;
  }

  return (
    <button onClick={() => record.save()}>
      Save {record.isNew ? '(Create)' : '(Update)'}
    </button>
  );
});
