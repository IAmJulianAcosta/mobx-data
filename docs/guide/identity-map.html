Identity Map

On this page

Identity Map ​

The Identity Map is mobx-data's caching layer. It ensures that for any given model type and ID, there is exactly one object instance in memory. This eliminates an entire category of bugs where different parts of your UI hold stale or conflicting copies of the same record.

How It Works ​

ts
const user1 = await store.findRecord('user', '1');
const user2 = await store.findRecord('user', '1', { reload: false });

console.log(user1 === user2); // true — same object reference

When the store receives data for a record that already exists, it merges the new data into the existing instance rather than replacing it. This means:

  • All existing references remain valid
  • MobX reactions fire automatically
  • No manual cache invalidation needed

Two-Level Cache ​

The identity map uses a two-level structure:

IdentityMap
  ├── 'user'
  │     ├── '1' → User { id: '1', name: 'Alice' }
  │     └── '2' → User { id: '2', name: 'Bob' }
  ├── 'post'
  │     ├── '10' → Post { id: '10', title: 'Hello' }
  │     └── '11' → Post { id: '11', title: 'World' }
  └── ...

First level: model type (string) → second level
Second level: record ID (string) → record instance

Accessing the Cache ​

Synchronous Reads (Peek) ​

Read from the cache without triggering network requests:

ts
// Single record
const user = store.peekRecord('user', '1'); // User | null

// All loaded records of a type
const users = store.peekAll('user'); // RecordArray<User>

Live Arrays ​

peekAll returns a live RecordArray. It updates reactively as records are added or removed:

ts
import { autorun } from 'mobx';

const users = store.peekAll('user');

autorun(() => {
  console.log(`${users.length} users in cache`);
});

await store.findRecord('user', '3');
// Console: "3 users in cache" — updated automatically

Merge Behavior ​

When the store pushes data for an existing record, attributes are merged:

ts
// Record already in cache: { id: '1', name: 'Alice', age: 30 }
store.push({
  data: { type: 'user', id: '1', attributes: { name: 'Alice Updated' } },
});

const user = store.peekRecord('user', '1');
console.log(user.name); // 'Alice Updated'
console.log(user.age);  // 30 — preserved from before

This is especially useful for partial updates, WebSocket events, or responses that only include changed fields.

Unloading Records ​

Remove records from the identity map when you no longer need them:

ts
// Single record
store.unloadRecord(user);

// All records of a type
store.unloadAll('user');

// Everything
store.unloadAll();

Unloading does not delete records on the server — it only removes them from local memory.

Cache Coherence ​

Automatic ​

The identity map stays coherent automatically through:

  • findRecord — updates the existing instance with fresh data
  • save — applies the server response onto the existing record
  • push — merges incoming data (WebSocket, SSE, etc.)
  • destroyRecord — removes the record after successful server deletion

Manual Refresh ​

Force a reload from the server:

ts
await user.reload();
// or
await store.findRecord('user', '1'); // always fetches by default

Use { reload: false } to only fetch if the record isn't cached:

ts
const user = await store.findRecord('user', '1', { reload: false });

Performance Characteristics ​

  • Lookup by ID: O(1) — it's a Map lookup
  • Peek all: O(1) — returns the pre-built RecordArray
  • Push (merge): O(attributes) — iterates changed attributes only
  • Memory: one object per unique record loaded

Best Practices ​

  1. Don't hold onto IDs when you can hold references — since the identity map guarantees instance identity, hold the record reference directly
  2. Use peekRecord for synchronous reads — avoid unnecessary network calls when data is already cached
  3. Unload sparingly — the identity map prevents duplicates, so large caches are fine for most apps
  4. Trust the merge — let the store handle updates; don't try to manually sync state
